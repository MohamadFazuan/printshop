# Printshop

Type a prompt, pick a paper size, get a print-ready PDF at exactly that size.

Built for print shops and designers who want artwork out of a description without opening a design tool. Every generated variant is kept at full resolution; the one you pick also becomes a PDF whose page is the real physical size you asked for.

---

## Install

Download the installer for your machine from the Releases page.

**macOS (`.dmg`)** — the app is not code-signed. On first launch macOS will refuse it:

> "Printshop" cannot be opened because it is from an unidentified developer.

Right-click the app in Applications → **Open** → **Open**. Once only. If macOS instead says the app is *damaged*:

```bash
xattr -dr com.apple.quarantine /Applications/Printshop.app
```

**Windows (`.exe`)** — also unsigned. SmartScreen will show *Windows protected your PC*: click **More info** → **Run anyway**.

Signing removes both warnings and costs an Apple Developer membership plus a Windows code-signing certificate. Neither is in place yet.

## Setup

Printshop has no server, no accounts, and no API keys anywhere in it. Artwork is generated by **[Codex CLI](https://developers.openai.com/codex/cli)** running on your own ChatGPT plan, so there is no per-image charge.

Two things must be true on the machine:

1. Codex CLI installed
2. `codex login` done — or use **Sign in to Codex** in Settings

Without Codex the app cannot generate at all, and says so on the main screen rather than failing at the moment you press Generate.

## Know this before you sell a job

The image model renders at most **1536 px on the long edge**. That is a hard ceiling, and it decides what this tool can and cannot be used for:

| Size | Resolution you get | Verdict |
|---|---|---|
| A6, 4 × 6 photo | ~248 DPI | fine |
| A5 | 176 DPI | fine |
| A4 | 124 DPI | soft — proofs and internal work only |
| A3 | 88 DPI | soft |
| A2 / A1 | 62 / 44 DPI | not print-ready |
| A0, bunting 2 × 5 ft | 31 / 26 DPI | not print-ready |
| Banner 4 × 10 ft | 13 DPI | not print-ready |

The readout under **Size** states this per job in plain words, and the threshold moves with the piece — a bunting read from across a room is judged against 75 DPI, a flyer in the hand against 300. It will not tell you a banner is fine.

**For bunting and banner work**, treat the output as a concept or a background element, not the final file: take the generated art into your design software, rebuild the type as vector, and scale from there. Exports do upscale with Lanczos plus a light unsharp pass, which keeps flat-vector edges from turning to mush — but no upscaler invents detail that was never rendered.

## Using it

| Control | What it does |
|---|---|
| **Prompt** | What to draw. Plain description works; art-direction language works better. |
| **Size** | ISO (A3–A6), US (Letter, Legal, Tabloid), photo sizes in inches and cm, Square, or **Custom** in `mm / cm / in / px`. |
| **Landscape** | Swaps width and height. |
| **DPI** | Converts `px` custom sizes, and drives the resolution readout. 300 is the print default. |
| **Engine** | *Codex CLI* (no per-image cost, minutes) or *OpenAI API key* (billed, seconds). |
| **Quality** | `low` for drafts, `high` for the final. Price moves roughly 15× between them. API engine only — Codex picks its own. |
| **Variants** | How many images to generate at once, 1–4. |
| **Fit** | *Fill page* crops the overflow; *Fit with margin* keeps the whole image and leaves white. |
| **Format** | PDF, PNG, JPEG or TIFF. Raster exports are rendered at the page size for your DPI — A4 at 300 gives 2480 × 3508. |
| **Colour** | RGB or CMYK. CMYK needs a profile (below) and is unavailable for PNG. |
| **Watermark** | Off / On plus the text. Tiled diagonally across the whole page — harder to crop off than a corner mark. Vector text in PDFs, composited into raster exports. |

Clicking a variant selects it for export. To inspect one properly, use the **⤢** button on the tile or double-click it — that opens the full image with its pixel dimensions and filename. Arrow keys move between variants, `Esc` or a click on the backdrop closes. Zooming never changes which variant is selected.

The line under Size shows the page in your unit, in PDF points, and the **effective print resolution**. Below 150 DPI it says so — an A3 from a 1024 px render prints soft, and it is better to know before the paper is used.

The estimated cost sits next to **Generate** and updates as you change the controls. It is charged to your key, so it is shown before the call, never after.

### Codex CLI

With Codex installed and logged in, it does two jobs — both on your ChatGPT login, neither touching your API key:

**Generates the artwork.** Set **Engine** to *Codex CLI* and Generate runs Codex's built-in image model, writing the PNGs straight into the job folder. No per-image charge. Expect roughly a minute per image, against seconds for the API — the trade is time for money.

**Writes the prompt.** The **Improve with Codex** button above the prompt turns a rough brief — *"birthday poster, dinosaur theme, kid turning 5"* — into an art-directed one, told which orientation it is composing for. **Revert** puts your original text back. Works with either engine.

Codex chooses its own output dimensions, so the resolution readout under the variant grid reports what actually landed rather than what was requested. Check it before printing large.

Printshop searches the usual install locations; a GUI app does not inherit your shell `PATH`, so set the full path in Settings if Codex lives somewhere unusual. Without Codex, the engine option is disabled and everything falls back to the API key.

### Signing in to Codex

Settings shows your Codex login state. **Sign in to Codex** runs `codex login`, which opens your browser — if your ChatGPT account uses Google, click *Continue with Google* on that page. The credentials go to Codex, never through Printshop. **Sign out** runs `codex logout`.

### CMYK

CMYK is a colour space, not a file format, and converting without a profile produces wrong colours that still look plausible on screen. So Printshop will not guess: point Settings at the `.icc` profile your press uses (**Profile…**), and the profile is test-converted on selection so a bad one fails there instead of halfway through a job.

No profile on hand? macOS ships `/System/Library/ColorSync/Profiles/Generic CMYK Profile.icc`, which is fine for proofing and wrong for a real press run — ask your printer for theirs.

PNG is always RGB; the option disables itself rather than pretending. CMYK PDFs embed CMYK pixels, and the watermark is drawn in CMYK ink so the RIP has nothing left to convert.

### While it runs

A Codex job takes minutes, so it reports as it goes: a progress bar, a running clock, and a live log of what Codex is doing.

The percentage is counted from **images actually written to disk**, not guessed from elapsed time — at `1/2 images · 50%` there really is a finished PNG in the folder. Before the first image lands there is nothing honest to count, so the bar sweeps rather than showing a made-up number.

The log is Codex's own event stream (`codex exec --json`), so a stall shows its last real step instead of a spinner. The API engine reports the same way, with less to say — one request, one result.

### Output

```
~/Printshop/2026-08-04/red-mountain-poster-a1b2/
  01.png                                    generated, full resolution, kept
  02.png                                    generated, full resolution, kept
  red-mountain-poster-a1b2-A4.pdf           export: RGB, no watermark
  red-mountain-poster-a1b2-A4-PROOF.pdf     export: watermarked
  red-mountain-poster-a1b2-A4-CMYK.tiff     export: CMYK separation
```

Filenames carry the colour space and watermark, so a proof can never quietly overwrite the press-ready file. An export that would land on an existing name gets `-2`, `-3` instead of replacing it.

Change the output folder in Settings. Nothing is ever deleted.

## Development

```bash
npm install
npm start     # run the app
npm run verify  # headless checks on the size/PDF logic — no key, no network
```

Build installers locally:

```bash
npm run dist:mac -- --arm64   # Apple Silicon .dmg
```

**Installers cannot be cross-built.** `sharp` carries a native binary per platform, so each installer has to be produced on a machine of that architecture — an Intel `.dmg` built on Apple Silicon ships arm64 binaries and crashes the moment a user exports. Do not force the missing binaries into `dependencies` either: that makes `npm ci` impossible on every platform at once.

`.github/workflows/build.yml` therefore builds on three runners — `macos-latest` (Apple Silicon), `macos-13` (Intel) and `windows-latest` — each installing its own native binary. Push a `v*` tag or run the workflow manually, then collect the artifacts. `npm run verify` gates every build.

Regenerate the app icon after editing `build/make-icon.js`:

```bash
node build/make-icon.js
```

### Layout

```
src/core.js              units, presets, pricing, PDF geometry — pure, no Electron
src/main.js              OpenAI call, file writes, key storage, IPC — all privileged code
src/preload.js           the entire renderer↔main surface
src/renderer/            UI; no filesystem, no network, no key
test/verify.js           exercises src/core.js directly
build/make-icon.js       generates build/icon.png with no image dependency
```

Sizes live in one table in `src/core.js`, declared in their native unit — adding a paper size means adding one row. Pricing is a table in the same file; verify it against <https://openai.com/api/pricing/> before trusting the estimate.

## Limits

No bleed or crop marks, no multi-page documents, no job history browser, no auto-update. Generated artwork is subject to OpenAI's usage policies; a rejected prompt surfaces their message verbatim.
